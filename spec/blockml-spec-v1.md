# BlockML 语言规范 v1.3

Status: **normative** · Date: 2026-10-30 · 后缀 `.blockml`

BlockML 是给**架构图**用的 diagram-as-code 语言。作者只描述语义：有哪些块（node）、块之间靠什么连（edge）、它们怎么分组（group）。**布局与渲染质量由平台负责**：默认分层布局、共享端口、法线出线、标签避让、避障与跨线跳弧都不依赖手写样式；编辑器拖过节点后只把 `at`（以及拖动控制点后的 `via`）写回同一份文件，图和文件仍然一致。

```blockml
diagram {
  title: "订单平台"
}

group core "核心服务"
group data "数据面"

node order "order-service" {
  group: core
  kind: service
  tech: "Spring Boot 8080"
}

node pg "PostgreSQL" {
  group: data
  kind: db
}

edge order -> pg "JDBC" {
  kind: sql
}
```

---

## 1. 设计约束

| # | 约束 | 后果 |
| --- | --- | --- |
| C1 | **文件即事实源**：语义 + 编辑器写回的坐标都在同一份文本里 | 不需要 sidecar 布局文件，拖动结果可 review |
| C2 | **可 round-trip**：parse → serialize → parse 必须得到同一棵树 | 工具可以安全重写文件 |
| C3 | **只写改动的键**：编辑器拖完只回写 `at` / `via` | 手写注释和格式不被破坏 |
| C4 | **未知即降级，不阻断**：未知 kind / 未知 `x-` 属性给 warning | 旧工具能打开新文件 |
| C5 | **无外部依赖**：解析器和渲染器都不需要运行时库 | 内网双击即用 |
| C6 | **渲染质量由平台保证**：默认布局、端口、法线、标签、避障与跳弧统一实现 | 作者不写 `at` / `route` / `color` 也不降低质量下限；语言只留语义 |

非目标：流程图语义（分支/泳道）、类图关系（继承/实现）。BlockML 不追求把任意图排成最优布局，但默认视图**必须**满足 §7.5 的渲染质量契约。

## 2. 词法

### 2.1 文件

- 扩展名 `.blockml`，UTF-8，`LF` 或 `CRLF` 均可。
- 一个文件 = 一张图（`diagram`）。多张图请用多个文件。

### 2.2 注释

```blockml
# 行注释，到行尾
// 同样等价
```

块内块外都可写。注释不进入 AST 的语义，但实现**必须**在格式化时保留。

### 2.3 标识符

```
[A-Za-z_][A-Za-z0-9_.-]*
```

用于块 id、`group` 引用、`kind` 值。大小写敏感，推荐 `kebab-case` 或 `snake_case`。

### 2.4 字符串

```blockml
tech: "Spring Boot 8080"
note: "第一行\n第二行"
note: """
原样多行文本
  保留缩进
"""
```

- 普通字符串用双引号，支持转义 `\"` `\\` `\n` `\t`。
- 三引号字符串**原样保留**内容（不解析转义），去掉开头换行和结尾换行。
- 单引号不合法（报 BLK003）。

### 2.5 其它字面量

| 类型 | 写法 | 例 |
| --- | --- | --- |
| number | 整数或小数 | `12`, `-3.5` |
| boolean | 小写 | `true` / `false` |
| pair | 两个 number，逗号分隔 | `340, 280` |
| list | 方括号，逗号分隔 | `[a, b, "c d"]` |
| ident | 见 2.3 | `service` |
| color | `#rgb` / `#rrggbb` | `#4f46e5` |

`pair` 的两个分量按出现顺序解释为 `x, y`。

### 2.6 结构符号

`{` `}` `[` `]` `:` `,` `->`。语句以**换行**或 `;` 结束。

块内属性之间可以用换行、分号或逗号分隔，所以小块的属性可以写在同一行：

```blockml
node a "A" { kind: db, group: core }
edge a -> b "调用" { kind: sql }
```

缩进不参与语法，仅用于可读性。

## 3. 文档结构

一个文档由 0..n 个顶层块组成，顺序任意（引用可前向）。

```
document  := diagram? group* node* edge*
diagram   := "diagram" STRING? block
group     := "group" IDENT STRING? block
node      := "node" IDENT STRING? block
edge      := "edge" IDENT "->" IDENT STRING? block
block     := "{" (property NEWLINE)* "}" | ε
property  := IDENT ":" value
```

- 块头后面的标题可省略，缺省用 id。
- `{ }` 可省略：无属性时直接写一行。
- **空块 `{ }` 与省略等价**。

### 3.1 diagram

```blockml
diagram "标题" {
  title: "订单平台架构画布"
  subtitle: "diagram-as-code"
  version: "1.3"
}
```

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 文件名 | 画布标题 |
| `subtitle` | string | — | 副标题 |
| `version` | string | `"1.0"` | 目标规范版本 |
| `theme` | ident | `light` | **兼容保留**。阅读器主题由查看器/编辑器决定，新文档不再输出 |
| `direction` | ident | `TB` | **兼容保留**。默认分层布局不再读取，新文档不再输出 |
| `route` | ident | `curve` | **兼容保留的查看器预设**：`curve` / `orthogonal`，等价于 `render --route`。新文档不再输出；两种风格由平台统一实现同一套端口、法线与标签规则（§7.3） |

新文档只写 `title` / `subtitle` / `version`。旧文件里的 `theme` / `direction` / `route` 继续解析，行为保持可读，但不再作为作者必须掌握的语义。

### 3.2 group

```blockml
group core "核心服务" {
  note: "下单、库存、支付三个服务"
  src: "docs/architecture/README.md:5"
}
```

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `label` | string | 覆盖块头标题 |
| `note` / `src` | string | 详情面板内容 |
| `color` | color | **兼容保留**。缺省按平台调色板分配，新文档不再输出 |

组的框由**成员节点的包围盒**自动算出，不能手写坐标。

### 3.3 node

```blockml
node order "order-service" {
  group: core
  kind: service
  tech: "Spring Boot 8080"
  note: "下单主链路，写 orders 库"
  src: "docs/architecture/README.md:5"
  tags: [core, java]
}
```

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `group` | ident | — | 必须指向已声明的 group |
| `kind` | ident | `service` | 见 §5 |
| `label` | string | 块头标题 | 覆盖显示名 |
| `tech` | string | — | 卡片副标题（一行，超长截断） |
| `note` | string | — | 详情面板正文，可多行 |
| `src` | string | — | 出处，约定 `文件:行` |
| `tags` | list | `[]` | 供过滤/搜索 |
| `at` | pair | 平台布局 | **编辑器回写**：节点左上角世界坐标。手写可选（旧文件兼容），新文档不写 |

### 3.4 edge

```blockml
edge app -> sandbox "ACP POST + SSE" {
  kind: acp
  src: "AgentsAcpClient.java:843-857"
}
```

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `kind` | ident | `rest` | 见 §5 |
| `label` | string | 块头标题 | 线上标签，可省略 |
| `bundle` | ident | — | 同名连线的汇流组：共用公共端点与一段主干，再分叉到各自对端。**语义属性**，`curve` / `orthogonal` 都生效 |
| `note` / `src` | string | — | 详情面板内容 |
| `via` | pair | `0, 0` | **编辑器回写 / 兼容保留**：控制点相对两端点中点的偏移。新文档不写 |
| `dash` | boolean | 按 kind | **兼容保留**：强制虚线/实线，新文档不写 |

规则：

- `from` 与 `to` 必须存在（BLK007）。自环允许。
- 边的箭头永远指向 `to`。
- 同一对节点可以有多条边；渲染器**必须**自动错开，作者不需要为每条边手写 `via`。
- 同一节点同一侧被 ≥3 条边使用时，最多只能出现 **2 个**附着点：一个入站、一个出站；`bundle` 组各占一个独立附着点。曲线与正交共用这套端口（§7.3）。
- 每条边在端点处沿边框**法线**出线：先走 8–24px 直段，再弯向主体；切线相对法线的偏差 ≤ 0.5°。
- 标签中心到本边路径的距离 ≤ 8px；不得压住节点、分组标题或其它标签。
- 连线不得穿过任何非端点节点；两条线交叉时统一画跳弧。

## 4. 类型与解析

### 4.1 属性值必须匹配合法类型

```blockml
kind: "service"     # ✅ 字符串会被当作 ident 接受，但 fmt 输出裸 ident
tags: [core, java]  # ✅ list
# 旧文件兼容：at / via 只接受 pair，新文档不写
at: 340, 280        # ✅ pair
at: "340, 280"      # ❌ BLK006（字符串不是 pair）
```

### 4.2 未知属性

- `x-` 前缀：**保留**，任何块均可写，实现放行且不报错。
- 其它未知键：warning `BLK005`，值丢弃。

### 4.3 未声明 group

`group: foo` 而 `foo` 未声明 → error `BLK008`，该节点视为无组。

### 4.4 重复 id

同一文档内 `node` / `group` 的 id 各自唯一 → 否则 error `BLK004`，保留第一个。

## 5. kind 词表（v1 内置）

`kind` 只影响**视觉**（节点色、线段样式），不影响语义。实现必须内置下表；未知值降级并给 warning `BLK009`。

### 5.1 节点 kind

| kind | 含义 | 建议色 |
| --- | --- | --- |
| `service` | 自有服务 | `#4f46e5` |
| `ui` | 界面 / 前端 | `#64748b` |
| `db` | 数据库 | `#10b981` |
| `cache` | 缓存 | `#ef4444` |
| `idp` | 身份提供方 | `#f59e0b` |
| `acp` | 执行面 / ACP 运行时 | `#0ea5e9` |
| `model` | 模型网关 | `#14b8a6` |
| `channel` | 外部渠道 | `#ec4899` |
| `ext` | 其它外部依赖（默认降级目标） | `#8b5cf6` |

### 5.2 边 kind

| kind | 含义 | 建议线型 |
| --- | --- | --- |
| `rest` | HTTP / REST | 实线 |
| `acp` | ACP 协议 | 实线 |
| `sse` | 单向事件流 | 虚线 |
| `sql` | 数据库访问 | 实线 |
| `rpc` | 服务间 RPC | 实线 |
| `oidc` | 身份 / 令牌 | 虚线 |
| `llm` | 模型调用 | 实线 |
| `mcp` | MCP 工具面 | 虚线 |
| `ws` | 长连接 | 虚线 |
| `gate` | 准入 / 闸门 | 点线 |
| `opt` | 可选 / 弱依赖（默认降级目标） | 点线 |

边 kind 的色值保留给图例与检查器做语义提示；画布上的连线颜色改由两端节点 kind 决定（见 §7.3）。

## 6. 诊断

诊断对象：

```ts
interface Diagnostic {
  severity: "error" | "warning";
  code: string;        // BLKxxx
  message: string;
  line: number;        // 1-based
  column: number;      // 1-based
  hint?: string;       // 一句话修复建议
}
```

| 码 | 级别 | 含义 |
| --- | --- | --- |
| `BLK001` | error | 无法识别的语句 |
| `BLK002` | error | 块未闭合（到 EOF 仍在块内） |
| `BLK003` | error | 字符串未终止 |
| `BLK004` | error | id 重复 |
| `BLK005` | warning | 未知属性（非 `x-` 前缀） |
| `BLK006` | error | 属性类型不匹配 |
| `BLK007` | error | 边端点不存在 |
| `BLK008` | error | 引用了未声明的 group |
| `BLK009` | warning | 未知 kind，已降级 |
| `BLK010` | warning | `version` 高于实现支持 |
| `BLK011` | error | 块头缺必填字段 |
| `BLK012` | error | 颜色格式错误 |

**有 error 时不得渲染**（可渲染上一次成功的结果）。**只有 warning 时必须正常渲染**。

## 7. 布局语义

### 7.1 坐标系

- 世界坐标，单位 px，原点左上，y 向下。
- `at` 是节点左上角；节点尺寸由渲染器决定（建议 200×62，随标题自适应）。
- 组框 = 成员节点包围盒 + 内边距（建议左右 30、上 34、下 30）。

### 7.2 默认布局

缺 `at` 的文档一律使用 `layered`：每个 group 占一列，列序按组内节点最浅依赖深度。渲染器**不得**把默认布局写回源文件。

- 手写/回写的 `at` 覆盖默认位置；只覆盖该节点，不改变其它节点。
- 拖过一个节点后，其余节点保持原位；再次打开文档时布局稳定。
- 缺 `at`、也没有任何样式属性的文档，一次渲染即必须满足 §7.5。
- 显式重排（`layered` / `pipeline` / `snowflake` / `compact`）仍可由 CLI 或编辑器入口触发；这是破坏性操作，会覆盖所有 `at`（`via` 仅作为兼容字段保留）。

### 7.3 边的走线（两种风格共用）

`curve` 与 `orthogonal` 共享同一套平台契约，作者不需要为走线手写任何样式：

- **端口**：每个节点每条边框最多两个普通附着点（入站 / 出站各一），`bundle` 组各占一个；同一组内的边共用附着点。端口由 `planPorts` 统一分配。
- **法线出线**：每条边在端点沿边框法线走 8–24px 直段，再弯向主体；端点切线相对法线的偏差 ≤ 0.5°。
- **避障**：连线不得穿过任何非端点节点的外框。曲线先做控制点候选搜索，找不到净空时退化为圆角折线绕行；正交先过滤穿节点的车道，仍被挡时用 Z 形多绕一步。
- **标签**：标签中心落在本边路径上（距路径 ≤ 8px），沿路径滑动避开节点、分组标题、其它标签；`bundle` 标签不落在共享主干旁。
- **跳弧**：两条线交叉时，绘制顺序靠上的一条在交点画小圆弧跳过另一条；两种风格一致。
- **着色**：连线从起点节点 kind 颜色（浅）过渡到终点节点 kind 颜色（实），箭头取终点色；边 kind 只决定实线 / 虚线 / 点线。
- **适应窗口**：`fit` 的边界包含节点、分组、连线与标签的外框，任何标签都不得被视口裁掉。

曲线：从两个共享端口各出法线直段，经一个在路径上的控制点用两段三次贝塞尔相连；`via` 只作为编辑器的兼容偏移，不再是作者调线的手段。

正交：从共享端口垂直出入，沿水平/垂直车道走，转折圆角半径不超过相邻两段各自长度的一半；`via` 不参与正交走线。

`bundle`：同名边在公共端点合并为一条主干 + 多条支线，两种风格都生效；主干若会穿过非端点节点，则放弃主干、只保留共享附着点，各边分别绕行。

### 7.4 回写契约

交互式编辑器在以下时机回写，且**只改这两个键**：

| 动作 | 回写 |
| --- | --- |
| 拖动节点结束（可多选整组拖动） | 每个移动节点的 `at: x, y` |
| 拖动边控制点结束（仅编辑态） | `via: dx, dy` |

回写必须保留：注释、块顺序、其它属性、未修改的格式。建议实现为「按行定位 + 只替换目标键」。

演示态（§10）禁用拖动，因此不产生任何回写。

### 7.5 渲染质量契约（验收）

以下指标对**没有 `at`、没有样式属性**的文档也必须成立（默认 `curve` 与 `orthogonal` 预设分别验收）：

| 指标 | 判据 |
| --- | --- |
| 同侧端口 | 同一节点同一侧 ≥3 条边时，普通附着点 ≤ 2（一入一出），`bundle` 另计 |
| 端点法线 | 每条端点切线相对边框法线的偏差 ≤ 0.5° |
| 标签贴合 | 标签中心到本边路径的最近距离 ≤ 8px |
| 标签避让 | 标签与节点、分组标题、其它标签的矩形交集面积 = 0 |
| 节点避让 | 非端点节点内部的路径采样点 = 0 |
| 交叉跳弧 | 两条线相交处必须有跳弧；未跳弧的交叉 = 0 |
| 视口完整 | 连线与标签的外框都在适应窗口内 |
| 默认布局 | 缺 `at` 的文档一次渲染即满足以上全部指标；拖一个节点不移动其它节点 |

## 8. 序列化（canonical form）

工具产出（而非用户手写）的规范格式：

1. 块顺序：`diagram` → `group`（按声明序）→ `node` → `edge`。
2. 属性顺序：`group` `kind` `label` `tech` `at` `note` `src` `tags`。
3. 缩进 2 空格；块之间空一行。
4. pair 写作 `x, y`；ident 不加引号；string 一律加引号。
5. 空属性块折叠为单行块头。

## 9. 版本与演进

- `version` 是**目标**版本，不是文件版本。实现支持 `1.x` 即接受 `1.0`–`1.99`。
- 次版本新增：只增属性或 kind，不改变既有语义。
- 主版本变更：必须提供迁移说明与转换脚本。
- 未来（非 v1）：块级样式 `style kind service { color: … }`、子图嵌套、边链 `a -> b -> c`。

## 10. 渲染最小集（实现契约）

一个合格的 BlockML 阅读器至少要提供：

1. 渲染 group 框、node 卡片（标题 + tech）、edge（曲线或正交） + 标签，并满足 §7.5。
2. 图例（按出现的 kind）。
3. 两档显示模式，随交付的 HTML **默认演示态**：
   - **演示态**：无点阵网格、无分组折叠点、无连线控制点手柄；节点不可拖动；选中节点/连线与详情面板仍可用。
   - **编辑态**：点阵网格、折叠开关、控制点手柄、拖动、框选与多选工具条可用；拖完按 §7.4 回写。工具条提供「编辑 / 预览」切换。
4. 节点拖拽（Shift / Ctrl 多选后可整组拖动），并遵守 §7.4 回写；仅编辑态。
5. 边选中 + 控制点拖拽，并遵守 §7.4 回写；仅编辑态。
6. 缩放 / 平移 / 适应窗口（适应范围包含连线与标签，见 §7.3）。
7. 导出 SVG。
8. 语法错误定位到行，错误时不覆盖上一次成功渲染。
9. 悬停或选中节点时，高亮与它相连的边并淡化其余元素。
10. 提供至少一种显式重排算法入口（见 §7.2）。
11. 分组折叠与隐藏：group 框右上角提供折叠开关；折叠后组成员与相关边不绘制，组框收缩为带成员/连线计数的胶囊；隐藏的 group 与 node 连同其边一起不绘制。**可见性是视图状态，不进文件、不写回源码**；提供「全部显示」恢复。
12. 走线预设：`render --route curve|orthogonal`。这是查看器选择，不属于文档语义；旧文件里的 `diagram.route` 继续兼容。

建议但非必需：导出 PNG、深色主题、按 kind 过滤。
